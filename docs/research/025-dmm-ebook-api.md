# DMM.com Webサービス電子書籍データ調査

## 1. 目的

DMM.com Webサービス v3 を使い、一般向けDMMブックスの電子書籍コミックから
mankenで利用できる漫画単行本の書誌情報を取得できるか確認する。

この文書は2026年8月7日時点の調査結果であり、確定仕様や実装指示ではない。
API IDとアフィリエイトIDは `.env` で管理し、認証情報を含むURLや生レスポンスは
リポジトリへ保存しない。

## 2. 調査方法と根拠

調査では次の根拠を区別した。

1. DMM公式ヘルプと参加規約
2. 認証付きDMM.com Webサービス v3の実レスポンス
3. 出版社公式の商品情報との比較
4. APIリファレンスを参照する既存クライアント実装

DMM Webサービスの公式APIリファレンス `https://affiliate.dmm.com/api/` は、
通常のWeb取得環境では地域制限ページへ転送された。ユーザー環境のブラウザーでは
年齢確認ページまで到達したが、調査では年齢確認を代行していない。

このため、現行リファレンス本文で直接確認できなかった項目は、実レスポンスと
出版社公式情報が一致していても、フィールド名だけで共通書誌へ変換しない。

## 3. 利用前提と認証情報

DMM公式ヘルプでは、DMM WebサービスをDMMのデータベースへ外部からアクセスする
アフィリエイト向けAPIとして案内している。利用には次が必要である。

- DMM会員登録
- DMMアフィリエイト登録
- DMM WebサービスのAPI利用登録
- API ID
- アフィリエイトID

本プロジェクトではアフィリエイト承認済みで、API IDとアフィリエイトIDを
利用できる状態になっている。

認証値はクエリパラメータとして送信し、成功・失敗のどちらのJSONレスポンスにも
`request.parameters` として反映される。したがって、値そのものだけでなく、
完全なリクエストURLと無加工レスポンスも秘密情報として扱う必要がある。

既存の `.gitignore` は `.env` と `.env.*` を除外している。今回のRaw JSONは、
認証値を既知値で置換した後だけ、コミット対象外の `__sandbox/` に保存した。

## 4. APIと一般向けコミックフロア

公開資料から確認した主なAPIは次のとおり。

| API | 用途 | 今回の確認 |
| --- | --- | --- |
| `FloorList` | サービス・フロア一覧 | 実行済み |
| `ItemList` | 商品検索 | 実行済み |
| `AuthorSearch` | 著者一覧 | 実行済み |
| `SeriesSearch` | シリーズ一覧 | 今回は未使用 |
| `GenreSearch` | ジャンル一覧 | 今回は未使用 |
| `MakerSearch` | メーカー一覧 | 今回は未使用 |

`FloorList` の2026年8月7日時点の結果は次のとおりである。

| site | service | floor | floor ID |
| --- | --- | --- | --- |
| `DMM.com`（DMM.com（一般）） | `ebook`（DMMブックス） | `comic`（コミック） | `19` |
| `FANZA`（FANZA（アダルト）） | `ebook`（FANZAブックス） | `comic`（コミック） | `82` |

一般向け電子書籍コミックは、次の条件で取得できた。

```text
site=DMM.com
service=ebook
floor=comic
```

FANZAは今回の対象外である。`service` と `floor` だけでは一般向けとFANZAを
区別できないため、実装する場合は `site=DMM.com` も固定条件にする必要がある。

## 5. ItemListの検索条件とページング

実レスポンスと境界値確認から、今回使用した主なパラメータは次のとおりである。

| パラメータ | 実測結果 | mankenでの判断 |
| --- | --- | --- |
| `keyword` | 商品検索は成功するが、タイトル専用ではない | `Title` へ直接対応させない |
| `cid` | コンテンツID指定に使用できる候補 | 個別商品取得用の候補 |
| `article` / `article_id` | 既知の著者IDで商品を絞り込めた | ID取得方法が別途必要 |
| `hits` | 1以上100以下。0と101はHTTP 400 | `Limit` の上限候補は100 |
| `offset` | 1以上50000以下。0と50001はHTTP 400 | 1始まりのoffsetページング |
| `sort` | `rank`、`price`、`-price`、`date`、`review`、`match` でHTTP 200 | 公開する並び順は別途限定が必要 |
| `gte_date` / `lte_date` | 公開クライアントに定義がある | 今回は未検証 |
| `output` | `json` でJSONを取得できた | JSONを使用する |

未定義の `sort=invalid` もHTTP 200となり、今回の1件目は `rank` と同じだった。
不正な並び順をAPIが常に拒否するとは限らないため、実装側で許容値を検証する必要がある。

0件ではHTTP 200かつ本文内 `status=200` となり、`result_count=0`、
`total_count=0`、`first_position=1`、空の `items` が返った。

`total_count` は一般検索で50000となった。`offset` の上限も50000であるため、
それを超える全件走査はできない。カーソルへoffsetを入れる場合は、検索条件、
取得件数、並び順も拘束しないと同じページングを再現できない。

## 6. keywordと著者検索の適合性

3つの既知タイトルを `hits=10&sort=rank` で検索した。

| keyword | total_count | 上位結果の傾向 |
| --- | ---: | --- |
| `葬送のフリーレン` | 12 | 本編のほか、特装版、ファンブック、画集、アニメ副読本が混在 |
| `進撃の巨人` | 43 | 本編のほか、雑誌、関連本、別シリーズが混在 |
| `転生したらスライムだった件` | 175 | 上位10件中、同名本編は1件だけで、別作品が多数混在 |

この結果から、`keyword` はタイトル専用検索でも、入力全体の完全一致検索でもない。
結果を受信後にタイトル一致だけを残しても、API側の `total_count` とページングの意味は
タイトル検索と一致しない。したがって、現在の `SearchBooksRequest.Title` へは
安全に対応できない。

著者名 `山田鐘人` を `ItemList.keyword` に指定すると13件となり、上位10件は
すべて `iteminfo.author` に同名を含んでいた。同じ著者ID `253195` を
`article=author&article_id=253195` に指定しても13件となり、上位10件は一致した。

一方、`AuthorSearch` の現行パラメータは `floor_id` と頭文字用の `initial` が中心で、
著者名 `keyword` は受け付けない。今回 `keyword=山田鐘人` を付けても無視され、
全48801件の先頭10件が返った。著者名から著者IDを直接解決する方法としては使えない。

以上から、DMMの `keyword` は `FreeText` の候補にはなるが、`Title` と `Author` の
意味をそのまま保証できない。取得元側のNOT条件も確認できず、`ExcludedText` を
後段フィルタだけで代替すると件数とページングが変わる。

## 7. 電子書籍コミック100件の項目出現率

`site=DMM.com&service=ebook&floor=comic&hits=100&sort=date` で、
2026年8月7日時点の先頭100件を集計した。

| 項目 | 値あり件数 |
| --- | ---: |
| `content_id` / `product_id` | 100 / 100 |
| `title` | 100 |
| `number` | 100 |
| `volume` | 85 |
| `date` | 100 |
| `isbn` | 0 |
| `jancode` | 0 |
| `URL` / `affiliateURL` | 100 / 100 |
| `imageURL` | 100 |
| `prices.price` | 100 |
| `comment` | 0 |
| `description` | 0 |

`content_id` と `product_id` は100件すべて同じ値だった。ただし、今回の結果だけで
常に同一と保証せず、取得元参照にはAPIの検索パラメータでもある `content_id` を
第一候補とする。

`iteminfo` の出現件数は次のとおりだった。

| iteminfoキー | 出現件数 |
| --- | ---: |
| `series` | 100 |
| `author` | 100 |
| `manufacture` | 100 |
| `genre` | 99 |

`iteminfo` の各要素は `id` と `name` を持ち、配列順で返る。著者の役割や読みは
含まれない。

最新100件には雑誌が15件、`GIGATOON` ジャンルが15件含まれた。
`【タテスク】` や `【タテヨミ】` の単話商品では `number` が4、20、32などを取り、
`volume` が欠落する例があった。`floor=comic` だけでは漫画単行本へ限定できない。

## 8. 代表3商品の比較

通常単行本3作品と、版違いの例を比較した。

| DMM商品 | `number` | `volume` | `date`の日付部分 | `prices.price` | `isbn` / `jancode` |
| --- | ---: | ---: | --- | ---: | --- |
| 葬送のフリーレン | 15 | 202 | 2025-12-18 | 583 | なし / なし |
| 進撃の巨人 | 34 | 252 | 2021-06-09 | 671 | なし / なし |
| 転生したらスライムだった件 | 32 | 194 | 2026-06-09 | 792 | なし / なし |

出版社公式情報との比較では、次を確認できた。

- 小学館eコミックストアの「葬送のフリーレン 15」は15巻、著者2名、税込583円で、
  DMMの `number`、著者順、価格と一致した
- 講談社の「進撃の巨人（34）」は紙版248ページ、電子版発売日2021年6月9日で、
  DMMの `volume=252` は紙版ページ数と一致せず、日付は電子版発売日と一致した
- 講談社の「転生したらスライムだった件（32）」は紙版176ページ、
  電子版発売日2026年6月9日で、DMMの `volume=194` は紙版ページ数と一致せず、
  日付は電子版発売日と一致した
- DMMの `manufacture` は3件で小学館または講談社となり、出版社と一致した

ただし、特装版「葬送のフリーレン（15）」では `number=1`、`volume=240` となり、
`iteminfo.series` も特装版商品名と同じ独立シリーズだった。DMM上の `number` は
シリーズ内の商品順としては使えるが、書誌上の巻数を常に表すとは限らない。

`volume` は電子商品のページ数に近い値と考えられるものの、出版社が示す紙版ページ数と
一致しない。公式APIリファレンスで電子書籍における定義を確認できるまでは、
共通 `PageCount` へ変換しない。

## 9. 共通モデルへの変換判断

### 9.1 そのまま利用できる候補

| DMM項目 | manken候補 | 判断 |
| --- | --- | --- |
| `content_id` | `BookSource.ID` | 取得元内商品IDとして利用できる |
| `URL` | `BookSource.URL` | 追跡情報のない商品参照URLとして利用できる |
| `title` | `Normalized.Title` | 分解せず商品タイトル全体を採用できる |
| `iteminfo.series` | `Normalized.Series` | 名称とDMM内IDを同じ要素に保持できる |
| `iteminfo.author` | `Authors`、役割なしの `Contributors` | 名前と順序だけを保持し、役割を推測しない |
| `service=ebook` | `PublicationMediumDigital` | 電子書籍フロアに限定した結果である |
| `iteminfo.genre` | `Subjects` | DMM固有SchemeとID・名称を区別する必要がある |
| `imageURL` | `Images` | 画像利用条件を利用者向け文書へ明記する必要がある |

### 9.2 初期変換に使わない項目

| DMM項目 | 理由 |
| --- | --- |
| `number` | 通常版では巻数と一致したが、特装版では書誌上の15巻に対して1となった |
| `volume` | ページ数に近いが、電子書籍での定義を公式リファレンスから確認できていない |
| `date` | 代表例では電子版発売日と一致したが、DMM側の項目定義を直接確認できていない |
| `isbn` / `jancode` | 最新100件と代表3作品で一度も返らなかった |
| `iteminfo.manufacture` | 代表例では出版社と一致したが、項目名は出版社を明示していない |
| `prices.price` | 現在価格らしいが、定価との区別、通貨、税込区分をレスポンスだけで確定できない |
| `comment` / `description` | 最新100件と代表3作品で存在しなかった |

`date`、`manufacture`、`prices.price` は実例との一致率が高くても、初期実装で
推測を避けるなら未設定とする。後続調査で公式の意味が確認できた項目だけを追加する。

## 10. 商品URLとアフィリエイトURL

通常商品URLとアフィリエイトURLは100件すべて異なった。代表商品では次の構造だった。

| 種類 | host | path・queryの特徴 |
| --- | --- | --- |
| `URL` | `book.dmm.com` | `/product/<series ID>/<content ID>/`。queryなし |
| `affiliateURL` | `al.dmm.com` | `lurl`、`af_id`、`ch` をqueryに持つ |

`BookSource.URL` は通常の `URL` を使用し、アフィリエイトURLを混同しない。
アフィリエイトURLは広告・販売用途の情報であり、将来必要になった場合も
書誌参照とは別のモデルで扱う。

## 11. 価格、画像、説明文の利用条件

DMMアフィリエイト参加規約は、商品紹介に使う画像を「広告コンテンツ等」とし、
DMMが許諾したものだけを利用できるとしている。また、広告掲載では必要に応じて
「広告」「宣伝」「プロモーション」「PR」等の表示が必要になる。

DMM公式ヘルプでは次を確認できた。

- 使用可能な商品メイン画像では拡大画像も利用できる
- 画像は直リンクとダウンロードのどちらも可能だが、ダウンロード済み画像の
  取り下げを求められる場合がある
- 画像加工は拡大・縮小だけが可能で、その他の加工は控える必要がある
- 商品紹介文とユーザーレビューは著作権保護のため引用できない

ライブラリが画像URLや通常商品URLを返すことと、利用者がアフィリエイト広告として
表示・保存・加工できることは同じではない。実装する場合は、DMMの現行規約と
画像利用条件を利用者向けガイドへ案内する必要がある。

一方、APIレスポンスの長期保存、キャッシュ、加工データの再配布を明示的に許可する
条項は今回確認できなかった。公開ライブラリとしてDMMデータを再配布するのではなく、
利用者自身の認証情報でAPIを呼ぶクライアントとして設計する場合でも、必要なら
DMMへ確認する。

## 12. エラー応答

実測したエラーはすべて、HTTPステータスと本文内 `result.status` がともに400だった。

| 条件 | HTTP | 本文 |
| --- | ---: | --- |
| `hits=0` / `hits=101` | 400 | `errors.hits` に下限・上限違反 |
| `offset=0` / `offset=50001` | 400 | `errors.offset` に下限・上限違反 |
| 認証パラメータなし | 400 | `errors.api_id` と `errors.affiliate_id` |
| 不正なAPI ID | 400 | `errors.api_id` |
| `site=INVALID` | 400 | `errors.site` |

成功時も本文に `status=200` があるAPIと、`FloorList` のように本文の `status` を
持たないAPIがある。後続実装ではHTTPステータスだけに依存せず、APIごとの正常構造と
エラー構造を検証する必要がある。

今回の確認だけでは、429、5xx、タイムアウト、レスポンス破損時の動作は確定しない。

## 13. 採用判断

DMM.com Webサービスは、DMMブックスの商品情報を取得する用途には有用である。
特に、商品ID、通常商品URL、シリーズID、著者名、画像URL、DMM固有ジャンル、
取得時点価格の候補を取得できる。

ただし、現行のmankenにおける漫画単行本のタイトル検索元としては採用しない。
理由は次のとおりである。

- `keyword` がタイトル専用でなく、検索結果のノイズが多い
- `floor=comic` に雑誌、縦読み単話、関連本、特装版などが混在する
- ISBNとJANが最新100件および代表3作品で返らない
- `number` が書誌上の巻数と一致しない版違いがある
- `volume`、`date`、`manufacture`、`prices.price` の意味を現行公式リファレンスから
  直接確認できていない
- `AuthorSearch` で著者名から著者IDを直接検索できない
- 現在の `Title`、`Author`、`ExcludedText` の意味とページングを維持できない

この判断はDMMを取得元候補から永久に除外するものではない。将来、次のいずれかを
満たす場合に再調査する。

- DMM側にタイトル専用検索、商品種別絞り込み、ISBN等が追加される
- mankenに取得元固有のフリーワード商品検索を扱う明確なユースケースができる
- 書誌検索とは別に、販売情報や画像を取得するモデルを設計する
- 現行公式リファレンスとAPIデータ利用条件を確認できる
