# Yahoo!ショッピング漫画商品データ調査

## 1. 目的

Yahoo!ショッピング商品検索API v3を使い、`bookfan` の紙書籍と
`ebookjapan` の電子書籍から漫画単行本の書誌情報を抽出できるか確認する。

この文書は 2026-07-31 時点の調査結果であり、確定仕様や実装指示ではない。
認証情報と生レスポンスはリポジトリへ保存しない。

## 2. 前提

- API:
  https://developer.yahoo.co.jp/webapi/shopping/v3/itemsearch.html
- エンドポイント:
  `https://shopping.yahooapis.jp/ShoppingWebService/V3/itemSearch`
- 紙書籍ショップ:
  `seller_id=bookfan`
- 電子書籍ショップ候補:
  `seller_id=ebookjapan`
- 書籍、雑誌、コミック親カテゴリ:
  `10002`
- コミック、アニメ本親カテゴリ:
  `10251`

タイトル検索では、原作小説や関連書を避けるため漫画カテゴリで絞る。
openBDなど、ISBNで1冊を取得する処理にはこのタイトル検索用制約を適用しない。

## 3. `bookfan` の実レスポンス

検索語 `ふつつかな悪女ではございますが`、新品、先頭10件を確認した。
カテゴリを指定しない検索では、次の種類が同時に返った。

- コミック単巻
- コミック特装版
- コミック全巻セット
- 原作小説
- 原作の掌編集

原作小説は `12492: 文芸書籍`、コミック商品は
`10251: コミック、アニメ本` の子孫カテゴリだった。したがって、
ショップだけでなくカテゴリによる絞り込みも必要である。

ただし、`10251` には全巻セット、コミック関連本、アニメ関連本も含まれ得る。
「漫画単行本」を保証するには、子カテゴリの採否と全巻セットの扱いを
追加調査する必要がある。

### 3.1 商品名

確認できた形式には次がある。

```text
タイトル 巻数/作画者/原作者
タイトル 巻数 特装版 /作画者/原作者/キャラクター原案
〔予約〕タイトル 巻数 /作画者/原作者/キャラクター原案
タイトル 1-10巻セット
```

`/` より後ろは著者表示順の候補になる。一方で、タイトル自体に `/` が入る場合、
著者が省略される場合、全巻セット、予約表示、特装版があるため、商品名だけで
すべてを確定しない。

### 3.2 商品説明

確認した `description` はHTMLの `<br>` 区切りで、次のラベルを含む場合がある。

```text
画:尾羊英　原作:中村颯希
企画・原案:ゆき哉
出版社:一迅社
発売日:2026年09月30日
シリーズ名等:ZERO−SUMコミックス
巻数:1巻
キーワード:...
```

ラベルなしで寄与者名だけが並ぶ商品や、一部ラベルが欠落する商品も確認した。
したがって、次の優先順位を候補とする。

1. 商品説明の役割ラベルから `Contributors` の役割を取得する。
2. 商品名の `/` 区切りから `Authors` の表示順を取得する。
3. 同一人物を完全一致で対応付け、役割と順序を合わせる。
4. 対応できない名前や未知のラベルを捨てず、役割不明として保持する。
5. 役割ごとに並べ替えない。

商品名と商品説明の表記が一致しない場合の採用規則は未確定である。

### 3.3 JANコード

確認したコミック単巻の `janCode` は、すべて `978` から始まる13桁で、
ISBN-13として妥当な形式だった。全巻セットでは空文字列だった。

`janCode` をISBN-13へ設定する場合は、少なくとも次をすべて確認する。

- ASCII数字13桁
- `978` または `979` で始まる
- ISBN-13のチェックディジットが正しい
- 漫画単行本の商品である
- 全巻セットなど複数冊商品ではない

条件を満たさない値はJANコードとして保持し、ISBNへ変換しない。

### 3.4 書誌項目の候補

| 共通概念 | 取得候補 | 注意点 |
| --- | --- | --- |
| タイトル | `name` | 予約、巻数、版、著者部分の分離が必要 |
| 巻数 | `description` の `巻数:`、`name` | ラベルがない商品がある |
| 版表示 | `name` の特装版など | 自由記述の調査が必要 |
| Authors順 | `name` の `/` 以降 | 著者省略や区切りの例外がある |
| Contributor役割 | `description` の役割ラベル | ラベルなし商品がある |
| 出版社 | `description` の `出版社:` | 比較的明示的 |
| 発行レーベル | `description` の `シリーズ名等:` | シリーズ名との区別が必要 |
| 発売日 | `description` の `発売日:`、`releaseDate` | 精度と値の優先順位が未確定 |
| ISBN-13 | 検証済み `janCode` | JANからの無条件変換は禁止 |
| 商品URL | `url` | 書誌レコードURLではなく販売URL |
| 商品画像 | `image`、`exImage` | 表紙以外の仮画像の場合がある |
| 販売情報 | 価格、在庫、予約状態 | `Book` ではなく `Offer` 候補 |

## 4. `ebookjapan` の確認結果

Yahoo!ショッピングのWebページ上では、`ebookjapan ヤフー店` に多数の商品が
掲載され、商品名に次のような形式が見られる。

```text
タイトル (巻数) 電子書籍版 / 著者
タイトル モノクロ版 (巻数) 電子書籍版 / 著者
```

Webページ:
https://store.shopping.yahoo.co.jp/ebookjapan/search.html

しかし、今回の有効なClient IDを使った商品検索API v3では、次のどちらも
正常応答の0件だった。

- `seller_id=ebookjapan` と検索語を指定
- `seller_id=ebookjapan` だけを指定

この結果と、ebookjapanの商品がYahoo!ショッピング商品検索APIの検索対象では
ないという前提から、本プロジェクトではYahoo!ショッピング経由の電子書籍検索を
採用しない。Webページを解析する代替実装も対象外とする。

Yahoo!ショッピング商品検索APIは `bookfan` の紙書籍検索だけに使用し、
電子書籍のタイトル検索には楽天Koboを使用する。

## 5. AuthorsとContributors

コミカライズ作品では、表示順が次のどちらにもなり得る。

```text
原作者、作画、キャラクター原案
作画、原作者、キャラクター原案
```

役割の優先順位で並べ替えると取得元の表示順を失うため、次の分担を候補とする。

- `Authors`
  - 著者として表示する名前の配列
  - 取得元が示す順序を維持する
  - 既存APIとの互換性と単純な表示に使う
- `Contributors`
  - 名前と役割を保持する
  - 取得元が示す順序を維持する
  - 役割不明の要素も保持できる

`Contributors` を役割別のマップや集合として管理せず、順序付きスライスとして
扱えば、`Authors` と役割情報の両方を維持できる。それでも `Authors` は、
利用者が役割を解釈せず表示する用途と既存互換のため残す価値がある。

## 6. 未決事項

- `10251` 配下で漫画単行本として採用する子カテゴリ
- 全巻セットを `Book` として返すか、検索結果から除外するか
- 特装版、限定版を版表示として抽出する規則
- 商品名と商品説明で著者名や順序が異なる場合の優先順位
- `画`、`漫画`、`原作`、`企画・原案` などの共通役割への対応
- `シリーズ名等` をシリーズ名と発行レーベルのどちらへ設定するか
- `releaseDate` と説明内の `発売日:` の優先順位
- 表記規則の変更を検知する実レスポンステストの方法

## 7. 調査時点の判断

- Yahoo!タイトル検索は、ショップと漫画カテゴリの両方で絞り込む。
- ショップ固有の明示ラベルは、検証後に書誌変換へ利用してよい。
- 商品名だけから役割を推測せず、商品説明の役割ラベルと組み合わせる。
- `Authors` と `Contributors` はどちらも取得元の順序を維持する。
- `janCode` はISBN-13として検証できた単巻だけISBNへ設定する。
- openBDなどのISBN検索には、タイトル検索用のカテゴリ制約を適用しない。
- Yahoo!ショッピング商品検索APIは `bookfan` の紙書籍検索に限定する。
- `ebookjapan` は実装対象から外し、電子書籍検索には楽天Koboを使用する。
