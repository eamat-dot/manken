# Backlog

現在のAPIの対象外とした機能や、着手時期を決めていない作業を記録する。
実施が決まった項目は、範囲と受け入れ条件を定めたTODOへ移す。
完了した作業や、現行実装の責務として確定した事項は記録しない。

## 検索機能

- マンガ単行本シリーズ検索
- 複数データ取得元の横断検索
  - 取得元ごとに異なる検索能力をどう指定するか
  - 取得元をまたぐ検索条件とLimitの意味
  - 取得元をまたぐカーソルとページングの規則
  - `NormalizedBook`、Raw response、または両方を返す必要性
- 検索結果の重複統合
  - ISBNなど信頼性の高い識別子で確実に統合できる範囲
  - タイトル、著者名、巻数、版違いなど推論を必要とする照合をライブラリの責務に含めるか

## 書誌データの変換

- MADBの人物読みの再調査
  - 同一Agent URI内に通常表記と読みがあり、言語タグも確認できる実例が得られた場合だけ着手する
  - または、直接 `schema:creator` と `dcterms:creator` のAgentを明示的に結び付ける取得元プロパティが確認できた場合に着手する
  - 着手時は、方式B・Cが安全な値を追加できるかを確認してから、ISBN参照、タイトル検索、著者検索、フリーワード検索ごとの性能を測定する

## 商品・販売情報

- 複数の販売系プロバイダを比較し、販売状態、在庫、送料、レビューなど未共通化の情報を共通モデルへ含める必要があるか判断する
- 書誌参照URLと販売商品URLの責務を整理する
- APIレスポンスの保存、画像利用、広告表示など、プロバイダごとの利用条件を利用者へ案内する範囲を整理する

## データ取得元

現在はMADB、Google Books、楽天Booksの書誌検索・ISBN参照、openBDのISBN参照を実装している。
未実装の取得元は、直前の取得元で確立したパッケージ構造、エラー処理、
テスト方法を反映しながら、詳細TODOを1件ずつ作成して調査・実装する。

各プロバイダの比較基準と既存調査の確認水準は
[プロバイダ検索・取得能力の比較](research/027-provider-capabilities.md)を参照する。
未実装プロバイダの調査では、同文書の標準チェックリストを使って不足項目を確認する。

現時点の主な候補は次のとおり。

1. 楽天Kobo API
2. Yahoo!ショッピング商品検索API
3. DMM.com Webサービス

楽天Koboは楽天Booksと異なり、電子書籍固有の商品番号、検索条件、変換規則を持つため、
別の調査・実装TODOにする。

Yahoo!ショッピングは、`bookfan` の紙書籍では実レスポンスを確認済みで、
`ebookjapan` は商品検索APIから取得できなかった。ほかの販売者を漫画・販売情報源として
利用できるかは未調査のため、実装対象を決める前に利用範囲を整理する。

DMM.com Webサービスは、現行の `keyword` がタイトル専用ではなく、ISBNや巻数にも
書誌検索上の制約があるため、漫画単行本の主要なタイトル検索元としては採用しない。
一方、DMMブックスの商品検索、商品URL、画像、価格候補などの情報源としては有用であり、
商品・販売情報プロバイダの実装候補として扱う。実装範囲は、他の販売系プロバイダとの
比較と共通モデルの要否を確認してから決める。

次の取得元は着手時期を決めていない。

- NDL 国立国会図書館サーチ

取得元を追加する場合は、HTTPステータスと共通の `ErrorKind` の対応を比較する。
利用にAPIキー、アプリケーションID、アフィリエイトIDなどが必要な場合も、
利用しないプロバイダの認証情報まで要求する構成にはしない。
