# 構想メモ

> [!IMPORTANT]
> この文書は、アイデアや検討事項を記録するための**構想メモ**であり、仕様書や実装指示書ではない。
>
> 記載内容には、未検証の案、矛盾、重複、過剰な要件、実現性の低い処理が含まれている可能性がある。また、記載されたロジック、処理順序、データ構造、画面構成などを、そのまま採用することを要求するものではない。
>
> 仕様書や実装計画を作成する際は、各項目を要件として機械的に転記せず、次の観点から再評価すること。
>
> * ユーザーが達成したい目的と、本質的に必要な要件を特定する
> * 重複する機能や責務を統合し、不要な機能を除外する
> * 処理順序、責務分担、データ構造を見直す
> * 実装コスト、保守性、拡張性、既存機能との整合性を考慮する
> * より単純で一般的な設計や、確立された手法で代替できないか検討する
>
> 特に、独自性の高い案が構造や処理を複雑化する場合は、その案自体を前提とせず、ユーザーの目的や背景を確認したうえで、より単純な代替案を提示すること。
>
> 判断が必要な事項については、AIが一方的に仕様を確定または実装せず、採用案、代替案、利点、欠点、影響範囲を整理してユーザーに提案すること。

## このファイルの役割

`manken` の将来案や比較検討中の案を記録する。
確定した内容は `docs/spec.md` または `docs/pkg/<package>/spec.md` へ移し、
実施する作業は `docs/todo/`、着手時期を決めていない項目は `docs/backlog.md` へ分離する。
