# mankenの構想

## 目的

漫画本のタイトルやISBNなどの書誌情報を、複数のGoプロジェクトから同じ方法で扱えるようにする。

外部サービスごとの通信方式、認証、レスポンス形式を利用側へ露出させず、
検索結果を共通の書籍モデルへ変換して返す。

## 最初に扱う範囲

最初のデータ取得元にはメディア芸術データベース（MADB）を使用する。
初期APIではマンガ単行本のタイトル検索に絞り、実データを確認しながら
取得項目と検索条件を確定する。

## 責務の分離

- `manken`
  - 書籍モデル、検索条件、検索結果、共通エラーを定義する
- `madb`
  - MADBへの問い合わせと共通モデルへの変換を担当する
- 将来のMCP実装
  - 検索APIをMCPツールとして公開する

検索ライブラリはMCP SDKへ依存させない。
MCPの仕様やトランスポートが変わっても、書籍モデルと検索処理を変更せずに済む境界を保つ。

## 方針

- 外部サービス固有の型を公開APIへ含めない
- 欠落する書誌項目を正常な状態として扱う
- 取得元にない情報をタイトルなどから推測しない
- リトライ、キャッシュ、ログ、並行実行は呼び出し側が制御する
- 仕様調査、API実装、MCP実装を別の作業として進める

確定したAPIは [共通API仕様](spec.md) と
[MADBパッケージ仕様](pkg/madb/spec.md) に記載する。
未確定の案は [構想メモ](idea.md)、将来対応は [backlog](backlog.md) へ分離する。
