# mankenの構想

この文書は、現在の実装と仕様書から、mankenの目的と責務分担を要約したものである。
将来の実装を拘束する設計指針ではない。実装または仕様書と食い違う場合は、
実装と仕様書を正として、この文書を更新する。

## 目的

漫画本のタイトルやISBNなどの書誌情報を、複数のGoプロジェクトから同じ方法で扱えるようにする。

外部サービスごとの通信方式、認証、レスポンス形式を利用側へ露出させず、
検索結果を共通の書籍モデルへ変換して返す。

## 現在の責務分担

- 外部サービス固有の型を公開APIへ含めない
- 欠落する書誌項目を正常な状態として扱う
- 取得元にない情報をタイトルなどから推測しない
- 現行ライブラリはリトライ、キャッシュ、ログ、並行実行を提供せず、呼び出し側が必要に応じて制御する
- 取得元の実データを確認してから共通化できる項目と検索条件を決める

## 文書の役割

現在の構造と責務分担は [アーキテクチャ](../ARCHITECTURE.md)、確定した公開APIは
[共通API仕様](spec.md)、取得元固有の仕様は `docs/pkg/<provider>/spec.md` に記載する。
未確定の案は [構想メモ](idea.md)、将来対応は [backlog](backlog.md) へ分離する。
