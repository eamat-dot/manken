# MADB検索APIの仕様調査

## 背景

- `manken` の初期APIでは、MADBに登録されたマンガ単行本をタイトルで検索する
- MADB固有のクラス、プロパティ、検索方法、ページング方法が未確定である
- 将来MCPサーバーから使用するため、構造化入出力とエラー変換に適したAPI境界を確認する必要がある

## 目的

- `docs/pkg/madb/spec.md` に残る未確定事項を、公式資料と実レスポンスに基づいて確定する
- Goコードの実装を始められるだけのリクエスト、レスポンス、変換規則を決める
- MCP側から利用する場合に不足する情報がないか確認する

## 非目的

- Goコードの実装
- テンプレートファイルの移行
- MCPサーバーの実装
- キャッシュ、自動リトライ、レート制限の設計
- MADB以外のデータ取得元の調査

## 調査項目

### MADBスキーマ

- [ ] マンガ単行本を示すクラスURIを公式スキーマで確認する
- [ ] タイトル、副題、シリーズ名、巻数に対応するプロパティを確認する
- [ ] `schema:creator` とpublisherの値がURIか文字列か確認する
- [ ] `schema:creator` から著者名を取得するために必要な関連を確認する
- [ ] creatorに含まれる役割と `Authors` へ変換する範囲を決める
- [ ] ISBN-10、ISBN-13、刊行日に対応するプロパティを確認する
- [ ] MADBの識別子、リソースURI、Web表示URLの関係を確認する
- [ ] 各項目が欠落または複数存在する実例を確認する

### タイトル検索

- [ ] MADBの全文検索機能の仕様と利用例を確認する
- [ ] `schema:name` の部分一致検索と全文検索の結果を比較する
- [ ] 完全一致、部分一致、表記揺れを含む検索結果を比較する
- [ ] 日本語、英数字、空白、引用符、バックスラッシュを含む入力を確認する
- [ ] SPARQLインジェクションを防ぐ文字列生成方法を決める
- [ ] マンガ単行本以外が混ざらない検索条件を確認する

### HTTP

- [ ] 公式エンドポイントを確認する
- [ ] GETとPOSTの対応状況を確認する
- [ ] リクエストのContent-TypeとAcceptを確認する
- [ ] SPARQL Results JSONのContent-Typeと構造を確認する
- [ ] 正常応答のおおよそのサイズを確認する
- [ ] 不正クエリ、過剰なLimit、タイムアウト時の応答を確認する
- [ ] HTTP 429と `Retry-After` の有無を確認する
- [ ] 利用条件、免責事項、サービス変更に関する注意事項を確認する

### 結果変換

- [ ] 複数bindingを1冊の `Book` へまとめる規則を決める
- [ ] `Authors` とpublisherの重複除去と並び順を決める
- [ ] ISBNの形式確認とISBN-10、ISBN-13への振り分け方法を決める
- [ ] 刊行日を文字列として保持する規則を決める
- [ ] 欠落項目を空文字列または空スライスへ変換できることを確認する
- [ ] 推測による補完が不要であることを確認する

### ページング

- [ ] 安定した並び順に使用できるキーを確認する
- [ ] `LIMIT` と `OFFSET` によるページングの安定性を確認する
- [ ] `Limit + 1` 件の取得で次ページを判定できるか確認する
- [ ] カーソルに保持する情報を決める
- [ ] カーソルとタイトル、Limitの不一致を検出する方法を決める
- [ ] カーソルの有効期間を設ける必要があるか判断する

### 公開APIとMCP

- [ ] `Book` の各フィールドをJSON Schemaへ表現できることを確認する
- [ ] `SearchBooksRequest` と `SearchBooksResult` がMCPツールへ過不足なく対応するか確認する
- [ ] MCP側で定義する最小 `BookSearcher` インターフェースを確認する
- [ ] エラー分類から、入力修正可能なエラーと外部サービス障害を区別できるか確認する
- [ ] MCP実装を同一モジュールと独立モジュールのどちらに置くか比較する
- [ ] Go向けMCP SDKの候補と依存範囲を確認する

## 調査結果の反映先

- [ ] 確定したMADB固有の契約を `docs/pkg/madb/spec.md` へ反映する
- [ ] 共通APIへ影響する決定だけを `docs/spec.md` へ反映する
- [ ] 未確定のまま残す事項と、その理由を該当する仕様書へ記載する
- [ ] 実装判断に必要な実レスポンス例を、認証情報を含まない形で記録する
- [ ] 実装TODOの項目を調査結果に合わせて更新する
- [ ] 将来対応と判断した項目を `docs/backlog.md` へ分離する

## 検証

- [ ] 公式資料のURLと確認日を記録する
- [ ] 同じ検索を複数回実行し、順序とページングを比較する
- [ ] 代表的な正常系、0件、欠落項目、複数値の応答を保存する
- [ ] 調査用クエリと結果の対応を第三者が追跡できるようにする
- [ ] `git diff --check` を実行する

## 受け入れ条件

- [ ] `docs/pkg/madb/spec.md` の初期実装に必要な未確定事項が解消されている
- [ ] 実装に必要なクラス、プロパティ、HTTP形式、変換規則が確定している
- [ ] ページングとエラー分類の方針が確定している
- [ ] MCPから利用するためのAPI境界に重大な不足がない
- [ ] Goコードを変更していない
