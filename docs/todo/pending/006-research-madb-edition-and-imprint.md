# MADBの版表示と単行本レーベルを調査

## 状態

ペンディング。

確定済みの仕様は
[TODO011](../done/011-implement-madb-edition-and-imprint.md)で実装済みである。
残っているのは、`schema:version` が存在する代表IDについて、
公式サイトの版表示とSPARQLの値を対照する追加調査だけである。
この追加調査はMADB初期実装の完了条件に含めず、他の書籍検索APIを調査して
共通モデルを再評価するときまで保留する。

## 背景

- 同じ作品の検索結果に通常版、新装版、愛蔵版、文庫版などが混在する
- MADB公式サイトの検索結果では「単行本レーベル」と「版表示」を確認できる
- 調査開始時のMADBクエリは `schema:brand` と `schema:isPartOf` を取得していなかった
- 調査開始時の `SeriesNames` は言語タグなしの `ma:seriesName` だけを取得しており、
  `動物のお医者さん` の確認結果では空になっている
- 版、判型、媒体種別、レーベルは別の概念であり、1つの種別へまとめると
  利用者が版を区別できない

## 目的

- MADB公式資料、SPARQLレスポンス、公式サイト表示の対応関係を確認する
- 「単行本レーベル」「版表示」「マンガ単行本シリーズ」を区別して定義する
- MADB固有の取得項目と共通 `api.Book` に必要な項目を決める
- 実装前に `docs/spec.md` と `docs/pkg/madb/spec.md` の仕様を確定する

## 非目的

- Goコードの実装
- SPARQLクエリと `api.Book` の変更
- 検索結果のソートとカーソルの変更
- タイトルや出版社から版またはレーベルを推測する処理
- MADB以外のデータ取得元の詳細調査
- 書店の商品分類や独自の版分類体系の作成

## 前提・制約

- 公式資料と実データを根拠とし、公式サイトの表示名だけから
  RDFプロパティを推測しない
- 言語タグ付きの読みと表示用の値を区別する
- 値が欠落するレコードを正常な状態として扱う
- `schema:brand`、`schema:isPartOf`、参照先のマンガ単行本シリーズを
  別々に確認する
- 共通モデルではMADB固有のプロパティ名をそのまま公開名にしない

## 対象範囲

### 対象

- マンガ単行本の単行本レーベル
- マンガ単行本の版表示
- `schema:isPartOf` が参照するマンガ単行本シリーズ
- 表示値、読み、URI、欠落値、複数値
- 共通モデルの項目名、型、JSON名、欠落時の表現

### 対象外

- 著者役割と巻数の正規化
- シリーズ順、刊行日順、巻数順の実装
- 画像、判型、価格、ページ数など今回の識別に直接使用しない項目

## 処理方針

1. 公式メタデータスキーマ仕様書で候補プロパティの定義と対象クラスを確認する
2. 対象レコードの全述語を取得し、公式サイトの表示項目と照合する
3. `schema:isPartOf` の参照先について、クラス、名称、レーベル、出版社を確認する
4. 表示値と `ja-hrkt` などの読みを区別する規則を整理する
5. 版表示、レーベル、シリーズの欠落、複数値、競合値を確認する
6. 共通モデルへ追加する項目とMADB内部だけに保持する項目を提案する
7. ユーザー承認後に仕様書へ確定事項を反映する
8. 確定仕様に基づく実装TODOを別に作成する

## 調査結果

調査日は2026年7月30日とする。公式資料には
[MADBメタデータスキーマ仕様書][madb-schema]を使用し、実データは
[SPARQL Query Service][madb-sparql]へ認証情報を使用せずPOSTして確認した。

### 公式スキーマ上の定義

| 概念 | 対象 | RDFプロパティ | 出現回数 | 意味 |
| --- | --- | --- | --- | --- |
| 単行本レーベル | マンガ単行本 | `schema:brand` | 0-N | 出版者が形式や頒布計画に基づいて設定する上位の書誌単位 |
| 版表示 | マンガ単行本 | `schema:version` | 0-N | 類似する内容の頒布物を識別する版、バージョン、エディション |
| マンガ単行本シリーズ | マンガ単行本 | `schema:isPartOf` | 0-1 | 単行本を一部として含むマンガ単行本シリーズ |
| 単行本レーベル | マンガ単行本シリーズ | `schema:brand` | 0-N | シリーズを構成する単行本の形式や頒布計画に基づく上位の書誌単位 |
| 版表示 | マンガ単行本シリーズ | `schema:version` | 0-N | 同じ作品に属する類似・関連シリーズを識別する版表示 |

`schema:brand` の読みは同じプロパティへ `ja-hrkt` 言語タグ付きリテラルとして
格納される。表示値は言語タグなしのリテラルである。

マンガ単行本シリーズは `class:MangaBookSeries` の独立したリソースであり、
単行本に直接記録されたレーベルや版表示そのものではない。

### 代表実例

| 種別 | MADB ID | タイトル | `schema:version` | `schema:brand` | `schema:isPartOf` |
| --- | --- | --- | --- | --- | --- |
| 通常版 | `M380671` | だから僕は、Hができない。 | `[通常版]` | ドラゴンコミックスエイジ | `C335424` |
| 新装版 | `M377325` | マンガ古事記 | `[2011年] 新装版` | 欠落 | `C352372` |
| 愛蔵版 | `M354575` | サルまん | `21世紀愛蔵版` | Big spirits comics | `C285334` |
| 完全版 | `M358795` | 見晴らしガ丘にて | `[完全版]` | 欠落 | `C280967` |
| 文庫版 | `M296746` | 対訳OL進化論 | `文庫版` | 欠落 | `C260649` |

`M292129` は `schema:brand` に `白泉社文庫`、`schema:isPartOf` に
`C262212` を持つが、`schema:version` は欠落する。レーベル名に「文庫」が
含まれていても、版表示が `文庫版` であると補完してはならない。

`M313606` は `schema:version` に `完全版` を持つ。同じ `C254067` を参照する
`M313608`、`M315172`、`M315173` には版表示がない。版表示の欠落だけを根拠に、
通常版または完全版のどちらかへ分類することはできない。

### 「動物のお医者さん」の参照関係

| 単行本 | 単行本のレーベル | 参照先シリーズ | シリーズ名 | シリーズのレーベル |
| --- | --- | --- | --- | --- |
| `M292128` | 花とゆめ増刊 | `C262213` | 動物のお医者さん | 花とゆめ増刊 |
| `M292129` | 白泉社文庫 | `C262212` | 動物のお医者さん | 白泉社文庫 |
| `M292127` | 欠落 | `C262214` | 動物のお医者さん | 欠落 |

いずれの参照先も `class:MangaBookSeries` である。調査開始時に取得していた
`ma:seriesName` が欠落していても、参照先の言語タグなし `schema:name` には
シリーズ表示名が存在する。

単行本と参照先シリーズのレーベルが異なる例も存在する。たとえば
`M1079781` の直接のレーベルは `藤子不二雄全集`、参照先 `C306332` の
レーベルは `虫コミックス` である。このため、参照先シリーズのレーベルで
単行本の欠落値を補完しない。

### 欠落と複数値

- マンガ単行本15,551件に `schema:version` があり、値は合計15,631件あった
- `M335551` は `第2版` と `コミック版` の2値を持つ
- `M346749` は `完全復刻版` と `豪華限定版` の2値を持つ
- `M479344` は3値を持つが、読みやシリーズ名に見える値が混在する
- 言語タグなしの `schema:brand` が複数ある単行本も存在する
- `M530976` の `schema:brand` には `A`、`C`、`L`、`SELECTION`、
  `アラ還 愛子ときどき母` があり、すべてを正しいレーベル名とは断定できない

公式スキーマ上の意味と実データの品質は分けて扱う。値を取得する場合も、
レーベル名や版表示らしい文字列へ推測で絞り込まない。

### 公式サイト表示の確認状況

2026年7月30日の自動確認では詳細項目と検索結果が描画されず、
ブラウザーコンソールでフロントエンドのJavaScriptエラーを確認した。
同日に手動で保存した検索結果、ID詳細HTML、スクリーンショットを使用し、
`M292129` は次のとおり対照できた。

| 公式サイトの表示 | 表示値 | SPARQL |
| --- | --- | --- |
| 単行本レーベル | 白泉社文庫 | 言語タグなしの `schema:brand` |
| 単行本レーベル（ヨミ） | ハクセンシャ ブンコ | `ja-hrkt` の `schema:brand` |
| 関連リソースのマンガ単行本シリーズ | 動物のお医者さん、`C262212` | `schema:isPartOf` の参照先 |
| 版表示 | 表示なし | `schema:version` の値なし |

検索結果にも `M292129`、`動物のお医者さん 第8巻`、発行者名、刊行日が表示され、
ID詳細URLへ遷移できることを確認した。

「単行本レーベル」と `schema:brand`、マンガ単行本シリーズと
`schema:isPartOf` の対応は公式サイトでも確認できた。版表示の欠落も
SPARQLと一致した。版表示が存在する代表IDの公式サイト表示との対照は
引き続き未完了とする。

## 確定した共通モデル

次の方針を共通仕様として確定し、TODO011で実装した。

- 単行本へ直接記録されたレーベルを `Imprints []string`、
  JSON名を `imprints` として共通モデルへ追加する
- 版表示を `EditionStatements []string`、JSON名を
  `edition_statements` として共通モデルへ追加する
- `schema:version` は0-Nで実データにも複数値があるため、単一文字列にしない
- `schema:isPartOf` の参照先から `SeriesID string` と
  `SeriesURL string` を設定する
- 参照先シリーズの言語タグなし `schema:name` を既存の
  `SeriesNames` へ追加し、`ma:seriesName` と完全一致で重複除去する
- 読みは共通モデルへ追加しない
- 文字列配列は既存項目と同様に空文字列を除外し、完全一致で重複除去して
  Goの文字列昇順にし、欠落時も空スライスにする
- `SeriesID` と `SeriesURL` は欠落時に空文字列にする
- 単行本へ直接記録されたレーベルと版表示だけを返し、参照先シリーズ、
  タイトル、出版社から補完または分類しない

公開構造体へのフィールド追加は既存Goコードのフィールド参照を壊さないが、
位置指定の複合リテラル、JSONの完全一致比較、生成済みJSON Schemaには影響する。
`SeriesNames` へ参照先シリーズ名を追加すると既存フィールドの内容も変わるため、
退行防止テストとCHANGELOGへの記載が必要になる。

`Labels` はUIの一般的なラベルやRDFの `rdfs:label` と混同しやすいため、
出版物の発行母体を示す一般的な英語である `Imprints` を採用した。
`Editions` だけでは版の識別子や構造化済み分類にも見えるため、
取得元の表示を保持することが分かる `EditionStatements` を採用した。

同じタイトルの異なる版を識別する場合、版表示だけでは欠落があり、
レーベルだけでは版を確定できない。MADB内のシリーズ単位の識別には
`schema:isPartOf` の参照先IDを主なキーとし、版表示とレーベルは
利用者へ根拠を示す項目として併用する。

確定仕様の実装は
[TODO011](../done/011-implement-madb-edition-and-imprint.md)で完了した。

### 確認クエリ

代表IDの全述語は次のクエリで再確認できる。

```sparql
SELECT ?resource ?property ?value WHERE {
  VALUES ?resource {
    <https://mediaarts-db.artmuseums.go.jp/id/M1034511>
    <https://mediaarts-db.artmuseums.go.jp/id/M292127>
    <https://mediaarts-db.artmuseums.go.jp/id/M292128>
    <https://mediaarts-db.artmuseums.go.jp/id/M292129>
  }
  ?resource ?property ?value .
}
ORDER BY ?resource ?property ?value
```

版表示の代表例は次の条件で確認できる。

```sparql
PREFIX rdf: <http://www.w3.org/1999/02/22-rdf-syntax-ns#>
PREFIX schema: <https://schema.org/>
PREFIX class: <https://mediaarts-db.artmuseums.go.jp/data/class#>

SELECT DISTINCT ?resource ?id ?name ?version ?brand ?series WHERE {
  ?resource rdf:type class:MangaBook ;
    schema:identifier ?id ;
    schema:version ?version .
  OPTIONAL { ?resource schema:name ?name . FILTER(LANG(?name) = "") }
  OPTIONAL { ?resource schema:brand ?brand . FILTER(LANG(?brand) = "") }
  OPTIONAL { ?resource schema:isPartOf ?series }
  FILTER(REGEX(STR(?version), "通常|新装|愛蔵|完全|文庫"))
}
ORDER BY ?version ?id
```

## リスク・懸念
