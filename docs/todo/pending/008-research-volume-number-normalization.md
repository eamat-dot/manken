# 巻数表記の正規化規則を調査

## 状態

ペンディング。

MADBの表記だけを基準に共通の巻数モデルを確定せず、他の書籍検索APIが
巻数の元表記と比較可能な値をどのように提供するか調査してから再開する。
それまでは、取得元の表記を `VolumeNumber` にそのまま保持する初期仕様を維持する。

## 背景

- MADBの `schema:volumeNumber` は文字列であり、同じ意味の巻数に複数の表記がある
- `__madb-result.json` では `1`、`v.1`、`第8巻`、
  `7　／　第7巻` などを確認した
- `第8卷` や `.1` など、字形や接頭辞が異なる値も想定される
- 現在の仕様は取得元の巻数表記をそのまま `VolumeNumber` に保持する
- 一律に整数へ変換すると、上巻、下巻、別巻、外伝、小数巻などの情報を失う
- 版ごとの並べ替えや他の取得元との比較には、元表記とは別の比較可能な値が必要である

## 目的

- MADBの巻数表記を実データから収集し、表記パターンを分類する
- 元表記を失わず、明確に判定できる巻数だけを比較可能な値へ変換する規則を決める
- 共通モデルへ正規化値を追加するか、取得元内部だけで使用するか決める
- 正規化できない値と曖昧な値の扱いを確定する

## 調査記録

- [MADB巻数表記の調査記録](../../research/008-madb-volume-number-normalization.md)
- 2026年7月30日に実データの収集と分類を実施した
- 規則案とモデル案は未承認であり、仕様には反映していない

## 非目的

- Goコードの実装
- `VolumeNumber` の元表記を正規化値で上書きすること
- タイトル、ISBN、刊行日から欠落した巻数を推測すること
- 新装版と通常版の巻数を同一シリーズとして統合すること
- 検索結果のソートとカーソルの実装
- 全文字列項目への一律のUnicode正規化

## 前提・制約

- `VolumeNumber` は取得元の表記を保持する
- 正規化値は元表記から一意に判断できる場合だけ設定する
- 全角、半角、旧字体、空白の違いを変換する範囲を項目単位で定める
- 数字が複数含まれる場合は、同じ巻数の併記か別の意味かを確認する
- 正規化できない値をエラーにせず、元表記とともに保持する
- MADBだけでなく、将来の他取得元でも意味が通じる項目名を検討する

## 対象範囲

### 対象

- アラビア数字、全角数字、漢数字
- `v.`、`vol.`、`第`、`巻`、`卷` などの接頭辞と接尾辞
- `7 ／ 第7巻` のような同値併記
- 上巻、下巻、中巻、前編、後編、別巻、外伝、番外編
- 小数、枝番、合本、巻数範囲、複数巻収録
- 空値、不正値、競合する複数値

### 対象外

- 版表示、レーベル、シリーズの識別
- タイトル文字列からの巻数抽出
- 巻数順によるページング

## 初期例

次の期待値は仮説であり、調査後に確定する。

| 元表記 | 正規化候補 | 判断 |
| --- | --- | --- |
| `1` | `1` | 明確 |
| `v.1` | `1` | 明確 |
| `.1` | `1` | 文脈を追加確認 |
| `第8巻` | `8` | 明確 |
| `第8卷` | `8` | 明確 |
| `7　／　第7巻` | `7` | 両側が同値なら明確 |
| `上` | なし | 数値へ変換しない |
| `1.5` | 要検討 | 整数型では保持できない |
| `1-2` | 要検討 | 範囲か枝番か確認が必要 |

## 処理方針

1. MADBの巻数値を重複除去して収集し、件数と代表IDを記録する
2. 数字、接辞、区切り、補助語のパターンに分類する
3. 明確に数値化できる値、補助的な順序を持つ値、正規化しない値を分ける
4. Unicode正規化を使用する場合の変更対象をコードポイント単位で確認する
5. 正規化値の型、欠落表現、JSON表現を比較する
6. 他の取得元にも適用できる共通契約か、MADB内部の補助値かを決める
7. ユーザー承認後に仕様書へ確定事項を反映する
8. 確定規則と代表値一覧に基づく実装TODOを別に作成する

## リスク・懸念

- 少数の実例だけで規則を決めると、古い書誌や合本を誤変換する可能性がある
- NFKCを一律適用すると、巻数以外の意味を持つ記号まで変換する可能性がある
- 数値だけでは上巻、別巻、小数巻、巻数範囲を表現できない
- 他の取得元が既に正規化済みの数値を返す場合、rawと正規化値の境界が異なる
- 正規化値を公開すると、将来の規則変更が互換性へ影響する
