# DMM.com Webサービスの電子書籍データを調査する

状態: 調査完了（2026年8月7日、現行のタイトル検索元としては採用見送り）

## 背景

- 現状:
  - mankenではMADBの書誌検索・ISBN参照と、openBDのISBN参照を実装している
  - DMM.comアフィリエイトの承認を取得し、アフィリエイトIDとAPI IDを利用できる
  - 認証情報は `.gitignore` 対象の `.env` に保存済みである
- 課題:
  - 商品情報APIが漫画単行本検索に必要な項目をどこまで返すか未確認だった
  - DMMブックスのWeb検索はISBN検索に対応しておらず、商品APIの `isbn` の実態も不明だった
  - `keyword` がタイトル専用検索ではないため、mankenの共通検索条件に対応できるか判断が必要だった
- 変更が必要な理由:
  - 実装TODOを作る前に、DMM.comを漫画書誌の検索元として採用する価値と、
    安全に共通モデルへ変換できる項目を判断する必要があった

## 目的

- このTODOで達成すること:
  - DMM.com Webサービス v3 の電子書籍コミック向けAPIを整理する
  - 実レスポンスで利用できる書誌項目、検索結果、境界値、エラーを確認する
  - mankenの検索条件と `api.NormalizedBook` への対応可否を項目ごとに整理する
  - DMM.comを現行の漫画単行本検索元として採用するか判断する
  - 調査結果を `docs/research/025-dmm-ebook-api.md` にまとめる
- 期待する利用者視点の結果:
  - DMM.comで何が検索・取得でき、何を共通書誌として保証できないかを実装前に把握できる

- 今回は扱わないこと:
  - DMM.comクライアントのGo実装
  - `api.Source` へのDMM追加
  - 共通モデルや検索APIの変更
  - DMMアフィリエイトリンクを表示するUIやWebサイトの実装
  - DMMブックスWebページのスクレイピング
  - FANZAの成人向け電子書籍データの調査

  - DMM側の検索機能またはmanken側のユースケースが変わり、再調査条件を満たした場合の再調査
  - DMMを商品情報取得元として採用すると決めた場合の仕様策定と実装

## 前提・制約

- 変更してよい範囲:
  - `docs/todo/025-research-dmm-ebook-api.md`
  - `docs/research/025-dmm-ebook-api.md`
  - 調査結果を反映する `docs/backlog.md`

  - Goコードと公開API

## 対象範囲

### 対象

- DMM.com Webサービス v3 の `FloorList`、`ItemList`、`AuthorSearch`
- 一般向けDMMブックスの `site=DMM.com&service=ebook&floor=comic`
- タイトル・著者・商品IDに関係する検索方法
- ページング、取得件数、並び順、エラー応答
- 電子書籍レスポンスの主要フィールドと出現率
- manken共通モデルへの対応候補
- API・画像利用条件のうちライブラリ設計へ影響する事項

### 対象外

- FANZA
- 動画、通販、レンタル等の他サービス
- DMMブックスの購入・閲覧API
- Webページからしか取得できない説明文等のスクレイピング
- アフィリエイト報酬の最適化

## 想定ユースケース

- 入力:
  - 漫画タイトル、著者名、DMMの商品ID等
- 実行:
  - DMM.com Webサービスの商品情報APIで一般向け電子書籍コミックを検索する
- 出力:
  - DMMの商品情報から、安全に意味を対応付けられる書誌項目と、対応できない項目を判断する
- 失敗時の扱い:
  - API仕様で確認できない項目と、実レスポンスで確認できなかった項目を区別して記録する
  - フィールド名や少数の一致例だけで共通書誌の意味を確定しない

## 処理方針

1. 公式ヘルプ、参加規約、既存クライアント実装から公開情報を整理する
2. 認証値を出力せず、一般向け電子書籍コミックの実APIを必要最小限の件数で確認する
3. 既知作品と出版社公式情報を比較し、変換できる項目と変換しない項目を分ける
4. 現在の共通検索条件を維持できるかに基づいて採用可否を判断する

## リスク・懸念

- DMM公式APIリファレンス本文は地域制限または年齢確認のため直接確認できなかった
- 成功・失敗レスポンスの `request.parameters` に認証値が含まれる
- `floor=comic` には単行本だけでなく、雑誌、縦読み単話、関連本、版違いが混在する
- `number`、`volume`、`date`、`manufacture` は名前や少数の一致例だけで共通書誌へ割り当てられない
- APIレスポンスの長期保存、キャッシュ、加工データの再配布条件は明示的に確認できなかった
- 画像とアフィリエイトURLを利用者が表示する場合は、DMMの現行規約と広告表示条件が別途適用される

## 未決事項

- DMMの商品情報を、書誌検索とは別の販売情報取得元として扱う将来ユースケース
- DMM側にタイトル専用検索、商品種別絞り込み、ISBN等が追加された場合の再評価
- `volume`、`date`、`manufacture`、`prices.price` の現行公式リファレンス上の定義
- APIレスポンスの長期保存、キャッシュ、加工データの再配布条件

これらは現行のタイトル検索元として採用しない判断を変える場合の再調査事項であり、
今回の調査TODOの完了を妨げない。
