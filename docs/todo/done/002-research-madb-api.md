# MADB検索APIの仕様調査

## 背景

- `manken` の初期APIでは、MADBに登録されたマンガ単行本をタイトルで検索する
- MADB固有のクラス、項目、検索、ページング、HTTP契約を実装前に確定する必要がある
- 将来MCPサーバーから使用できる構造化入出力とエラー境界を維持する

## 目的

- 公式資料と実レスポンスに基づき、MADBタイトル検索の契約を確定する
- Goコードの実装に必要なリクエスト、レスポンス、変換、エラー規則を決める
- 調査結果を `docs/spec.md` と `docs/pkg/madb/spec.md` へ反映する

## 非目的

- Goコードの実装
- MCPサーバーの実装
- キャッシュ、自動リトライ、クライアント側のレート制限
- MADB以外のデータ取得元

MCP実装の配置、SDK、ツールSchema、トランスポートの比較は
`docs/backlog.md` へ分離した。

## 実施結果

### MADBスキーマ

- [x] マンガ単行本のクラスを `class:MangaBook`、識別子を `cm101` と確認した
- [x] タイトル、副題、シリーズ名、巻数のプロパティを確認した
- [x] `schema:creator` が役割を含む文字列であることを確認した
- [x] `dcterms:creator` がAgentリソースを参照することを確認した
- [x] Agent参照がない実例を確認し、creatorのフォールバック規則を決めた
- [x] 著者、原作者、作画担当などを役割で分けず `Authors` へ返す方針を決めた
- [x] publisherが文字列で、役割や読みを含む場合があることを確認した
- [x] ISBNと刊行日のプロパティを確認した
- [x] MADB ID、リソースURI、Web表示URLの関係を確認した
- [x] 欠落、複数値、表記揺れ、不正に見える日付の実例を確認した

単一の正規タイトルを示す情報がないため、`Book` のタイトル、副題、
シリーズ名を文字列配列へ変更した。同じ種別のISBNが複数ある実例も確認し、
ISBN-10とISBN-13をそれぞれ文字列配列へ変更した。

### タイトル検索

- [x] MADBのAmazon Neptune全文検索拡張を確認した
- [x] 完全一致、`schema:name` 部分一致、全文検索を比較した
- [x] `match` が広すぎることを実レスポンスで確認した
- [x] `simple_query_string` の引用句と部分一致が代表検索で同じ件数になることを確認した
- [x] 日本語、空白、引用符、バックスラッシュ、全文検索演算子を含む入力を確認した
- [x] 全文検索層とSPARQL層の2段階エスケープを決めた
- [x] `rdf:type class:MangaBook` による絞り込みを決めた

`動物のおしゃべり` では、`match` が929件、引用句全文検索と部分一致が
それぞれ30件となった。

### HTTP

- [x] 公式エンドポイントを確認した
- [x] GETとPOSTの正常応答を確認した
- [x] POSTのContent-TypeとAcceptを確定した
- [x] SPARQL Results JSONのContent-Typeと構造を確認した
- [x] 101冊分の項目取得で約214 KiBとなることを確認した
- [x] 不正SPARQLがHTTP 400とJSON本文を返すことを確認した
- [x] 成功本文4 MiB、エラー本文64 KiBの読込上限を決めた
- [x] `X-RateLimit-Limit` と `X-RateLimit-Remaining` を確認した
- [x] 利用規約、免責、サービス変更の注意事項を確認した

`Retry-After` 付き429応答とレート制限の期間は、サービスへ負荷をかけずに
確認できなかった。実装では一般的な秒数形式とHTTP-date形式を扱う。

### 結果変換

- [x] bindingをリソースURI単位で1冊へまとめる規則を決めた
- [x] 複数値を完全一致で重複除去し、安定した昇順にする規則を決めた
- [x] creatorは役割を除いて名前へ変換し、publisherは推測で正規化しない方針を決めた
- [x] ISBNのチェックディジット検証と種別分けを決めた
- [x] 刊行日の精度と取得値を維持する規則を決めた
- [x] 欠落項目を空文字列または空スライスへ変換できることを確認した
- [x] タイトルなどから欠落項目を補完しないことを確認した

### ページング

- [x] MADBリソースURIを安定した一意キーとして採用した
- [x] `OFFSET` ではなくURIキーセット方式を採用した
- [x] `Limit + 1` 件で次ページを判定する方針を決めた
- [x] カーソルへバージョン、末尾URI、Limit、検索語ハッシュを保持する方針を決めた
- [x] カーソルと検索語、Limitの不一致を入力エラーにする方針を決めた
- [x] カーソルに有効期間を設けない方針を決めた
- [x] URI順の部分一致検索の再実行と、全文検索の次ページで順序、重複、連続性を確認した

全文検索の最大結果窓とMADB更新中のスナップショット一貫性は保証できないため、
制約として仕様書へ記載した。

### 公開APIとMCP境界

- [x] 複数値を保持できる `Book` へ共通モデルを更新した
- [x] `SearchBooksRequest` と `SearchBooksResult` をJSON Schemaで表現できることを確認した
- [x] MCP側の最小 `BookSearcher` インターフェースに重大な不足がないことを確認した
- [x] 入力修正可能なエラーと外部サービス障害を分類できる方針を決めた
- [x] MCP SDKへ検索ライブラリを依存させない境界を維持した
