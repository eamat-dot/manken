# MADBタイトル検索を空白区切りのAND検索へ変更

## 状態

2026年8月1日完了。

## 背景

- 現行実装は `simple_query_string` へタイトル全体を引用句として渡している
- MADBの環境では `simple_query_string` の演算子で複数語のANDを確実に表現できない
- 公式検索画面は空白区切り語をAND検索し、`うる星 復刻box` で4件を返す
- 公開SPARQLでも `query_string` の引用句と `AND` により同じ4件を再現できた

## 目的

- `Title` 内のUnicode空白で区切られた各語をAND条件にする
- 全文検索構文を利用者入力として解釈せず、安全にクエリを生成する

## 根拠

- [`../../research/014-madb-search-conditions.md`](../../research/014-madb-search-conditions.md)
- [`../../pkg/madb/spec.md`](../../pkg/madb/spec.md)

## 非目的

- ISBN、著者名、フリーワード、NOT検索の追加
- 公式サイト内部の `/es-api/` の利用
- 語形、表記揺れ、Unicode正規化の独自実装

## 前提・制約

- Go 1.26.0と標準ライブラリだけを使用する
- 既存の `Title`、Limit、URIキーセットページングを維持する
- タイトルの検索語数にライブラリ独自の上限を設けない
- 既存カーソルのタイトルハッシュ形式はこのTODOでは変更しない

## 処理方針

1. 前後の空白を除き、`strings.Fields` 相当の規則で検索語へ分割する
2. 各語の `\` と `"` を全文検索の引用句向けにエスケープする
3. 各語を二重引用符で囲み、` AND ` で結ぶ
4. `queryType` を `query_string`、`field` を `schema:name` にする
5. 完成した全文検索式をSPARQL文字列向けにエスケープする

## リスク・懸念

- 語数が増えると全文検索の負荷が増える
- `query_string` は不正構文をエラーにするため、エスケープ漏れが上流エラーになる

## 実装結果

- Unicode空白で分けた各語を引用し、`query_string` の `AND` で結合した
- 全文検索層とSPARQL文字列層のエスケープを分離した
- 公開API型、カーソル形式、Limit、URIキーセットページングを維持した
- タイトルの検索語数にライブラリ独自の上限を設けない仕様とした
- 実サービスで `うる星 復刻box` の4件を2ページに分け、重複なく取得した
