# 共通Bookを正規化値と取得元値へ再設計

## 状態

完了。

## 目的

利用者が通常参照する共通書誌情報と、正規化の根拠となった取得元別の値を分け、
漫画単行本向けのタイトル、巻数、版表示、著者、価格、判型などを一貫して返せる
`Book`モデルを設計、実装する。

## 確定した前提

- `Book`は利用者向けの正規化値と取得元別の値を分ける
- 正規化値は変更差分ではなく、通常利用に必要な共通書誌情報の完成形とする
- 加工不要な値も取得元から正規化値へコピーする
- タイトルを安全に分解できない場合は取得元タイトル全体を暫定値にする
- タイトル読みを安全に分解できない場合は正規化済みの読みを空にする
- `Volume`は `Number *int` と `Label string` だけを持つ
- 完結巻は `IsFinalVolume bool` で表す
- 並列タイトルは初期の正規化値へ追加しない
- 明示された巻数と版表示はタイトル検索の必須条件とする
- 初期実装では複数取得元のBookを自動統合しない

## 対象

- 共通 `Book`、正規化済み書誌型、取得元型の公開契約
- `Volume`、`Identifier`、`Contributor`、`Series`、`BookDate`、`Price`などの
  最小限の補助型
- 既存MADBレスポンスから新しい共通Bookへの変換
- 正規化値と取得元値のJSON表現
- 既存MADBテストと公開APIテストの更新
- `docs/spec.md`と`docs/pkg/madb/spec.md`の確定仕様

## 対象外

- Google Books、Yahoo!ショッピング、楽天Books、楽天Koboクライアントの実装
- 複数取得元の自動統合と競合解決
- 電子書籍をタイトルと巻数だけで同一商品と判断する処理
- 全ページを取得したシリーズ全体の巻順保証
- MADBのカーソルとSPARQLソートの変更
- 取得元の商品タイトルから巻数、版表示、除外表記を抽出する共通パーサー
- DMM.com API
- アダルトコミック専用検索

- 取得時点価格では `ObservedAt`を必須にする
- `TaxIncluded`は取得元で確認できる場合だけ設定する
