# MADBの受信rawレスポンスを保存できるようにする

## 背景

- `examples/demo-madb.go` が出力するJSONは、SPARQL Results JSONを
  `manken.SearchBooksResult` へ変換した後の値である
- 現在の実装は成功応答の本文を読み込んだ後、非公開型へ変換し、受信した本文を
  呼び出し元へ返していない
- 版、レーベル、著者の役割、巻数などの変換規則を検討するには、同一リクエストの
  変換前後を比較できる手段が必要である

## 目的

- MADBから受信したSPARQL Results JSONを、変換前の状態で直接確認できるようにする
- 1回の検索で得たrawレスポンスと変換済み検索結果を比較できるようにする
- rawレスポンスの確認機能をMADB固有の境界に置き、共通の `manken.Book` へ
  取得元固有の構造を持ち込まない

## 非目的

- `manken.Book` または `manken.SearchBooksResult` へのraw項目追加
- 任意のSPARQLを実行する汎用クライアントの提供
- MADBレスポンスの項目追加、役割判定、巻数正規化、ソート順の変更
- HTTPエラー本文を無制限に保存する機能
- rawレスポンスのキャッシュまたはリポジトリへの保存
- MADB以外のデータ取得元へのrawレスポンス機能追加

## 前提・制約

- 既存の `Client.SearchBooks` のシグネチャと動作を維持する
- MADBへのHTTPリクエストをraw取得のために二重送信しない
- 成功時の標準出力へJSON以外の案内を混在させない
- rawレスポンスの本文上限は既存の成功本文上限を維持する
- `__madb-result.json` など `__` で始まるローカル確認用ファイルは
  `.gitignore` の対象とし、成果物へ含めない
- 公開APIを追加する場合は、MADB固有の `madb` パッケージ内に限定する

## 対象範囲

### 対象

- `madb/client.go` の成功応答読込と検索結果変換の境界
- rawレスポンスと変換済み結果を同時に取得する最小のMADB固有API
- `examples/demo-madb.go` のraw出力オプション
- 単体テスト、README、MADB仕様書

### 対象外

- 共通モデルのフィールド変更
- SPARQLクエリの取得項目変更
- エラー分類と本文上限の変更
- integrationテストを通常の単体テストへ統合すること

## 想定ユースケース

- 入力: タイトル、取得件数、カーソル、rawレスポンスの出力先を指定する
- 実行: 1回のMADB検索でrawレスポンスを保存し、変換済み結果を標準出力へ出す
- 出力: 出力先には受信したJSON本文、標準出力には
  `manken.SearchBooksResult` のJSONだけを出す
- 失敗時の扱い: HTTP、本文読込、ファイル作成、JSON変換のどこで失敗したかを
  標準エラー出力と終了コードで示す

実行形は次を候補とする。

```powershell
go run ./examples/demo-madb.go `
  -title "動物のお医者さん" `
  -limit 100 `
  -raw-output __madb-result.json
```

## 処理方針

1. HTTP成功応答の本文を既存上限内で1回だけ読み込む
2. 同じ本文をrawレスポンスとして保持し、既存の変換処理にも渡す
3. `Client.SearchBooks` はrawレスポンスを破棄し、従来どおり変換済み結果だけを返す
4. raw取得用APIは変換済み結果とrawレスポンスを同時に返す
5. デモで出力先が指定された場合だけrawレスポンスをファイルへ保存する
6. 出力先の上書き可否と、変換失敗時に受信本文を残すかを実装前に確定する

## リスク・懸念

- `[]byte` や `json.RawMessage` をそのまま返す場合、呼び出し元の変更による
  予期しない共有が発生し得る
- ファイル出力の上書き規則が曖昧だと、既存の調査データを失う可能性がある
- 変換失敗時にrawを返さない設計では、最も確認したい不正レスポンスを保存できない
- rawレスポンスはMADBの仕様変更により構造や項目が変化する可能性がある

## 完了結果

- `Client.SearchBooksWithRawResponse` を追加し、変換済み結果、呼び出し元が所有する
  `[]byte` のrawレスポンス、エラーを返すようにした
- 2xx応答のJSON解析またはbinding変換に失敗した場合も、読み込み済みの
  rawレスポンスを返してデモから保存できるようにした
- `-raw-output` は新規ファイルだけを作成し、既存の調査データを上書きしない
- HTTPエラー本文と成功本文上限を超えた本文はrawレスポンスとして返さない
- 実サービスの1回の検索で変換済み2冊と、`head.vars` および
  `results.bindings` を含む2,798バイトのrawレスポンスを取得した
- `task all`、実サービス確認、`git diff --check` が成功した
