# MADBにNOT検索を追加

## 状態

2026年8月2日完了。

## 背景

- MADB Labが案内する `query_string` は `NOT` を使用できる
- 公開SPARQLで `"うる星" AND NOT "復刻box"` により対象語を除外できた
- 利用者入力を検索構文として公開すると、意図しない演算子解釈とエスケープ問題が生じる

## 目的

- 明示した語を含む漫画単行本を検索結果から除外できるようにする
- 検索構文を公開せず、ライブラリが安全なNOT式を生成する

## 根拠

- [`../../research/014-madb-search-conditions.md`](../../research/014-madb-search-conditions.md)
- [`017-add-madb-free-text-search.md`](017-add-madb-free-text-search.md)

## 非目的

- 利用者がAND、OR、NOT、括弧などの検索式を直接記述すること
- ISBN、日付、数値範囲の否定条件
- Agent参照だけに存在する著者名の除外
- 条件グループと任意の論理式を表す汎用クエリ言語

## 前提・制約

- `SearchBooksRequest` へ `ExcludedText string` を追加する
- 017のフリーワード対象フィールドと同じ範囲へ適用する
- `ExcludedText` だけの検索は禁止し、正条件を1つ以上必須とする
- 複数の除外語は、どれか1つでも含む本を除外する

## 処理方針

1. 除外文字列をUnicode空白で分割する
2. 各語を安全な引用句へ変換する
3. `FreeText` がある場合は、その全文検索式へ各語を `AND NOT` で追加する
4. `FreeText` がない場合は、正条件の種類にかかわらず、フリーワード対象フィールドに
   対する除外用全文検索を `MINUS` で結合する
5. `MINUS` の除外語は `OR` で結合し、どれか1語に一致する本を除外する
6. 除外語を正規化済み検索条件としてカーソルへ結び付ける

## リスク・懸念

- `FreeText` がない場合の `MINUS` は検索負荷が高くなる可能性がある
- 除外語が一般的すぎる場合、多数の候補を除外して空結果になり得る

## 未決事項

- なし

除外語数にはライブラリ独自の上限を設けない。実サービス検証でMADBの60秒制限を
超える条件が確認された場合は、上限の追加を別途検討する。

## 実装結果

- `SearchBooksRequest.ExcludedText` とデモCLIの `-exclude` を追加した
- `FreeText` がある場合は同じ全文検索式へ `AND NOT` を追加し、ない場合は
  12項目を対象とする `MINUS` で除外した
- 複数の除外語は、どれか1語を含む本を除外する規則にした
- 除外語を正規化してカーソルへ結び付け、ページ間で条件が変わる場合は拒否した
- Agentの `rdfs:label` は除外対象に含めなかった
- 実サービスでタイトル、ISBN、著者名、フリーワードとの組み合わせとページングを確認した
- 初回実測ではタイトル条件が約2.13秒、ISBN条件が約0.25秒、著者名条件が約15.99秒、
  フリーワード条件が約1.12秒で完了した
